# 审查核对表 · notifybus

> 本表只规定**交付格式与自检项**，不给出缺陷数量、位置或现象。
> 结论一律写进 `review/REVIEW.md`，本表**勿改**。

## 一、交付物

- 唯一交付物：`review/REVIEW.md`（本目录下）。
- 不改 `index.js`、`test/`、`check/`、`scripts/` 下任何文件；不新增、不提交源码或测试文件。
  临时复现程序可以写（放在仓库外的临时目录，或写完即删），但**提交前必须清掉**，
  仓库里除 `review/REVIEW.md` 外不得有任何改动。
- 提交前用 `git status --short` 自检：只应看到 `review/REVIEW.md` 一处改动。

## 二、保证判定表（必须逐条给判定）

`review/REVIEW.md` 的「保证判定」表必须把 README「对外保证」的 **7 条逐条列出**，
每条给出「违反」或「未违反」二者之一的明确判定，不许留空、不许写「不确定」。

- 判为**违反**的保证：必须在「结论清单」里有相应条目（保证编号一致）；
- 判为**未违反**的保证：「结论清单」里不得出现该编号的条目。

## 三、结论清单（四列，一行一条）

每条结论必须写清下面四列，缺一列算不合格：

| 列 | 含义 | 要求 |
| --- | --- | --- |
| 保证编号 | 被违反的是 README 里第几条对外保证 | 写编号（1~7） |
| 缺陷位置 | 出错的具体代码位置 | 写成 `文件名:行号`（如 `index.js:88`） |
| 最小复现 | 能稳定复现的最小命令 | 含**具体次数/深度**（如 `node --input-type=module -e "…"`，或一行可照抄的 Node 片段），可直接照抄运行 |
| 实际输出 | 跑出来的具体现象 | 期望什么 / 实际什么，**可判定**（具体数值、错误类型、计数等） |

> 结论至少 6 条，且合计覆盖 README 里至少 6 条不同的对外保证。

## 四、自检项

- [ ] 每条结论都能对应到 README 里**某一编号**的对外保证。
- [ ] 每条结论都给出了**可照抄复现**的具体命令与**具体现象**（期望 vs 实际）。
- [ ] 没有「可能有风险」「建议关注」「看起来不太对」「或许」这类**无法核对**的话。
- [ ] 四列表格之外，不夹带其他无关内容。

## 五、判定说明

- `bash scripts/check.sh` 是固定验收入口，只校验交付格式、可判定性与
  「保证判定 ↔ 结论清单」的自洽；结论**是否正确**由人按 README 保证逐条复核。
- 复现一律用 Node.js 标准能力（`node --input-type=module -e "…"`、或 `node --test`）
  加载本仓库代码；不要引入第三方依赖，也不要把临时程序提交进来。
